# 编辑器图片选择器 · 设计

日期：2026-09-29

## 问题

后台编辑器的工具栏：

- `image` 按钮只在光标处插入字面量 `![](url)`，作者必须自己去别处找到地址再手抄
- `📎` 用 `FileReader.readAsDataURL` 把整张图片转成 base64 塞进 `.md`
  一张图轻易变成 20 万字符，markdown 源文件从此不可读
- 上限写死 4 MB，不读「设置 → 单文件上限」

## 目标

1. 点 `image` 弹出媒体库，从已有图片里挑
2. 选择器里可以直接上传新图，上传完立刻出现在网格里
3. 插入的永远是真实地址，不是 base64
4. 正文里粘贴截图也走同一条路

## 决定

- 形态：**弹窗图层**（遮罩 + 缩略图网格），Esc / 点遮罩关闭
- 上传：选择器内含上传框，选完即时出现
- 历史 base64：**不做转换工具**，作者自行删除重写

## 服务端

### `GET <admin>/media.json`

登录后返回

```json
{ "files": [ { "name": "…png", "url": "https://…", "size": 1234, "mtime": "…" } ] }
```

选择器**打开时才请求**，所以打开编辑器不必等对象存储。

### `POST <admin>/media` 的 JSON 分支

现有浏览器表单路径完全不动。请求带 `Accept: application/json` 时，
上传成功返回 `{ ok, name, url, size }` 而不是 302。

## 前端

| 入口 | 行为 |
| --- | --- |
| `image` | 打开弹窗 → 取 `media.json` → 渲染网格 → 点图插入 `![标题](url)` |
| `📎` | 选文件 → POST 到 `/admin/media`（JSON）→ 插入 `![标题](url)`，带「上传中…」 |
| 正文粘贴截图 | 同上 |

大小上限从服务端渲染的 `data-max-bytes` 读取，跟随设置。

## 翻译

弹窗标题、空状态、上传中、文件太大、上传失败 —— 中英各一份。

## 验证

- e2e：`media.json` 返回刚上传的文件
- e2e：带 JSON Accept 时 `POST /admin/media` 返回 `{ url }` 而非 302
- 真实浏览器（playwright）：点 image → 弹窗出现 → 选图 → 正文出现 markdown

## 不做

- 不转换既有文章里的 base64
- 不做图片裁剪、压缩
- 不做图床之外的存储后端
