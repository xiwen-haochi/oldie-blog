我依然用纯文本文件写东西。理由很老派，但经得起时间检验。

<!-- more -->

## 文件是你的

一篇文章就是一个 `.md` 文件，放在 Git 仓库里。十年后不管哪个平台倒闭了，
你的文字都还在。迁移成本是零，因为根本没有需要迁移的东西。

```bash
# 文件名带日期，日期和 slug 自动识别
content/posts/2025-06-18-用-markdown-写博客这件事.md
```

## 前言（front matter）就是元数据

```yaml
---
title: "用 Markdown 写博客这件事"
date: 2025-06-18
description: "为什么我还是用纯文本写东西。"
tags: [markdown, 写作, 工具]
draft: false
---
```

上面这些字段直接喂给搜索引擎：`description` 进 `<meta>`，
`tags` 决定标签页和订阅源，`draft` 决定它会不会被访客看见。

## 中英文都没问题

写中文的时候，中英混排、行内代码、全角标点都能正常渲染，
阅读时间也会按中文的习惯来算（一个字大约算两个字符宽）。

> 互联网本来就是一个用来放文本的地方，别把事情搞复杂。

| 我想要的 | Markdown 给不给 |
| --- | --- |
| 标题层级 | `##` |
| 代码高亮 | ```js |
| 表格 | 管道符 |
| 强调 | **粗体**、==高亮== |

还有一件事：写完之后，点一下「下载 .TXT」，你会得到一份
